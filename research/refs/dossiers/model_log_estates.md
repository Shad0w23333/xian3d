# 住宅小区风貌建模记录（按档案与实景照片）

2026-09-28。数据：`research/refs/dossiers/residential.json`（93 个小区）与 `residential_notes.md`；照片为房天下实景图（每小区前 6 张）+ Esri z17 卫星对照图，
逐张目视后把观察写进 `tools/build_estates.py` 的 SPEC 表（每条都注明照片编号）。生成物 `public/data/estates_style.json`；
渲染在 `src/arch/bld-gen.js`（Worker 几何）、`src/arch/bld-shader.js`（立面着色器）、`src/arch/bld-estates.js`（大门）、`src/modules/buildings.js`。

## 1. 原则

- **不臆断**：只有实拍照片能看清住宅立面的小区才覆盖立面；只有售楼处沙盘/示范区/施工期/效果图、或照片认不出本小区楼栋的（11 个）不覆盖；
  无照片的小区（14 个）保持通用规则；本地 landuse 没有多边形的小区（融侨城、华远海蓝城、西安锦园有照片，辰宇世纪城、大华曲江公园世家、东新城市花园另计）范围无法确定，不覆盖。
  它们仍列在 json 与下表中（evidence = model / none / nopoly），便于以后补照片后直接加规则。
- **只改风貌与细节**：墙色、点缀色（腰线/窗套/顶部/竖向色带）、饰面（涂料/面砖/砖纹/仿石）、开间构件（阳台/飘窗/窗/空调百叶）、屋顶附属构件、
  层高（2.9–3.0 m，使渲染出的层数等于真实层数）。**楼的轮廓与高度一律不动**（buildings.bin 只读）；坡屋顶、塔冠、构架加在墙顶以上，与现有屋顶机房同一处理方式。
- **按楼型分档**：照片常常只拍到某一类楼（例如只拍到高层、洋房立面没拍到），所以规则按“高度 ÷ 3 m”估层数分四档：≤3 层 / 4–7 / 8–11 / ≥12，
  每档单独给规则；照片没拍到的档不覆盖。≤3 层的楼多为会所、底商、幼儿园等配套（档案 types 注明“未区分”），除非照片/卫星明确是别墅/联排，否则不覆盖。
- **看不出是哪栋的，不逐栋臆断**：照片里几种外墙并存又对应不到具体楼的（太白小区：米黄涂料/白色小瓷砖；丰盛园：肉粉涂料/橙褐面砖），按楼随机分配并写明；
  “部分高层有橙褐色竖向墙段”（富力城）这类只加到对应档位。
- **坡屋面按卫星逐栋取样**：照片/卫星显示有坡屋面的 11 个小区，下载 Esri World Imagery z18（≈0.49 m/px）瓦片，对每栋楼轮廓内缩 1.2 m 后取像素，
  去掉最暗 20%（阴影）与最亮 5%（高光）取中位色：红/橙色调（色相 ≤32° 或 ≥340°、饱和度 ≥0.2）判为红瓦。
  规则分两种：`color`（该档全部是坡屋面，颜色取卫星，例如中海铂宫红褐/深灰两色屋面逐栋区分）与 `red`（只有卫星判为红瓦的楼加坡顶，例如三棉/四棉社区、交大一村）。
- **大门只加照片里拍到的**（33 座）。位置不靠猜：用 Overture 2026-09 道路，取区内 service/residential/living_street 道路穿过小区边界的交点，
  按“离主干道近、门体 16×8 m 不压楼、门内 30 m 车道走廊不被楼挡”选一个；区内没有道路数据穿过边界的，取临主干道边界段上离转角最远、门内走廊通畅的一点（推定）。
  逐个核对图：`research/refs/dossiers/estates_check.jpg`（Esri z18 底图 + 小区边界红线 + 大门黄圈/车道方向；后几格为卫星屋面取样小区）。

## 3. 渲染实现

全城 23 万栋仍走原有 Worker 合批 + 远/近景两套材质（`bld-shader.js`），**没有新建任何建筑材质**：

- **数据**：每栋 4 texel 的数据纹理里，墙色/点缀色直接写成照片色；style 编号写进 flags（bit 6–13），bit 14 标记坡屋面；
  小区楼的玻璃色改由 style 给出，腾出的那一格存逐栋坡屋面颜色。style 参数（风格/饰面/阳台/竖向构件/基座层数/顶部层数/腰线周期/窗套/飘窗/防盗网/
  线脚色/基座色/顶部色/腰线色/窗框色/玻璃色/第二点缀色/开间周期）打包成一张 348×1 的 RGBA32F 小纹理 `uEst`，片元里只有小区楼才读（分支按楼一致，不发散）。
- **立面（着色器）**：
  - 饰面：涂料噪声 / 面砖 240×60 缝 / 砖纹（红砖浅灰勾缝、青砖深灰勾缝）/ 仿石 1.2×0.6 分格；
  - 基座 N 层（石材 + 水平分缝）、顶部 N 层变色、每层或每 N 层腰线（楼板处线脚 + 阴影）；
  - 竖向构件：阳台两侧色带（枫林绿洲橙/赭色，荣华EE康城黄/蓝交替）、中部楼梯间色带 + 半层错位窗（鸿基新城、曲江观邸百叶列）、
    通高壁柱（Art Deco / 新古典，每两开间一根，带侧面明暗）、整开间竖向色块（中铁缤纷南郡酒红、雅荷春天深灰、蔚蓝花城灰色窗间墙等）；
  - 开间组合按户型周期排布（南向：阳台 / 卧室窗或飘窗 / 厨卫窗 + 空调百叶；其他朝向：窗 + 百叶 / 小窗 / 窗），代替通用塔楼的随机开间；
  - 阳台：凸阳台玻璃封闭（下部实心栏板，老式住宅刷点缀色，如太白小区红褐）/ 凹阳台 / 开敞阳台金属栏杆（竖向栏杆 + 扶手，栏杆间看到阳台内侧）/ 玻璃栏板；
  - 窗套 + 窗台（新古典、红砖英式、洋房）、飘窗凸框 + 窗台下阴影、Art Deco 上下窗之间深色窗间墙（形成竖向窗带）、老式住宅防盗网与外挂空调；
  - 屋面以上的附属墙面（塔冠/中部升起）不开窗：Art Deco 竖向凹槽，新古典百叶盲窗 + 线脚。
- **屋顶几何（Worker，远景 + 近景都写进楼体网格，同一栋同一编号，远近交接一起塌缩）**：
  - 四坡顶：矩形度 ≥ 0.72 用主轴外接矩形 + 0.5 m 挑檐，否则沿轮廓内缩成坡；坡度 30°（别墅/洋房）、34°（高层坡顶塔冠）、50°（高科麓湾英式陡坡）；
    有挑檐底面；坡顶楼不再写被盖住的平屋面与女儿墙；瓦面在着色器里画：红/橙瓦为筒瓦（纵向瓦垄 + 法线起伏），灰瓦为错缝平瓦，逐片明暗、积灰；
  - Art Deco 收分塔冠：屋面上 2–3 级主轴对齐盒体逐级收进（≥60 m 三级），板楼按单元分两处；盒体先缩到轮廓以内再放；近景另加四角冲出屋面 3.5 m 的壁柱；
  - 新古典檐口：轮廓外挑 0.42 m 的檐口线脚（顶/底为环形面），≥8 层再加中部升起一层（板楼 38% 长 × 80% 宽，点式 44% 见方）；
  - 装饰构架：近景屋顶构件实例（梁柱框，柱距约 6 m，高 4.2 m，横向格栅梁），和机房一起实例化，没有新网格。
- **大门**：`bld-estates.js` 用盒体/圆柱/四棱锥/带拱洞的挤出墙体拼出 11 种门楼，全部合并成 1 个网格（顶点色 + 1 个材质，1 次 draw call），
  离所有大门 3.5 km 以外整体隐藏；基础埋入地面 0.6 m，坡地不悬空。

## 4. 性能

- 远景几何：+3.9 万三角形（5.225M → 5.264M，+0.75%）、+7.3 万顶点；超远景子集 +3.3 万三角形（3.121M → 3.153M）。
- 近景小块：有坡顶/塔冠的小块三角形增加（曲江观邸所在小块 2.78 万 → 3.16 万，+14%；中海铂宫小块因不再写被坡顶盖住的平屋面反而 −7%）；
  屋顶构件实例在坡顶小区减少（坡顶楼不放机房/热水器）。
- draw call：大门 +1；其余不变（没有新材质、没有新网格类型，装饰构架复用屋顶机房的 InstancedMesh）。
- 着色器：片元多约 150 行，非小区楼只多几个整型判断（`est` 为 false 时整段跳过）；小区楼多 4 次 texelFetch（348×1 小纹理，常驻缓存）。
- Worker 初始化：多一次按 500 m 网格的点在多边形判断（只对住宅类楼），离线测试（Node，同机多次）2.8–4.8 s 波动，差异在噪声内。

## 6. 已知差异与限制（全体通用）

- 立面细节由着色器按“开间 × 楼层”程序化绘制：窗、阳台、线脚、壁柱都是画在平面外墙上的（近景有视差凹进），不是真实的凹凸几何；
  户型开间组合（阳台/卧室窗/厨卫窗循环）是按一般西安住宅户型给的规律排布，不是逐栋照片对位。
- 楼体轮廓、高度沿用 buildings.bin（CMAB 2022 影像提取 + 另一路工作按成交记录层数修正），本次不改；
  因此照片里的退台、凹槽、转角弧面等形体不在本次范围。坡屋顶/塔冠按主轴外接矩形或轮廓内缩生成，是体量级近似。
- 颜色为照片目测色（档案 *_hex），受光照与白平衡影响；渲染时与通用建筑一样按“印象色 × 0.63”换算反照率，远处受雾与色调映射影响会偏浅。
- 坡屋面颜色取自 Esri 影像（年份与 CMAB 不完全一致），被树冠/阴影遮住的楼可能判错；大门位置 18 座为推定（见核对图）。
- 沙盘/示范区照片不作为立面依据（万科翡翠国宾、融创西安宸院等 11 个），无多边形的 3 个有照片小区不覆盖；补到实拍照片或多边形后，只需在 SPEC 表加一条再跑脚本。

## 8. 楼栋层数全面核实（2026-09-29）

用户反馈“还有很多小区层数不对”。本轮只动**楼高**（buildings.bin 的 heightDm/flags，按字节原位改写，轮廓/顺序不动），不动风貌规则；
调研方法、来源与抓取限制见 `residential_notes.md` §5，层数 → 楼栋的对应规则见 `tools/estate_floors.py` 头注释，
由 `tools/check_heights.py --fix` 调用（可重复运行，二次运行净变化 0 栋）。`tools/build_estates.py` 已按新楼高重跑
（只影响各档位楼栋计数与 2 个小区的卫星屋面列表，style/大门不变；新批次条目无照片，不写进风貌数据）。

### 8.1 问题在哪

- **CMAB 把高层成批低估**：原始高度是 CMAB（2022 影像）+ 回归模型，高层封顶 86–90 m，大量 30+ 层板楼只有 12–27 m。
  例：曲江华著中城成交/在售记录 34/35 层 113 条（共 149 条），CMAB 却有 24 栋“8–11 层”、19 栋“4–7 层”；Esri 倾斜影像上多边形内全是外露立面、长阴影的高层板楼。
- **上一轮“小区层数”规则的两个缺陷**：只用成交层数的集合（不含频次）、按集合下标分位，且只抬不降。
  盛世长安记录 18 层 120 条、30/31 层 15 条，却被抬成大片 31 层；安居客经纪人解读：“90% 是总高 18 层的板式小高层，其余是 11 层的和 2 栋高层”。
- **小轮廓错估**：紫薇苑·欧洲世家（别墅区，记录全是 4–6 层）里 150–220 m² 的轮廓被 CMAB 估成 12–26 层（36–76 m），影像上是别墅。
- **老公房偏矮**：太白小区、四棉社区、纺星一区、长庆未央湖花园等 6/7 层老小区，CMAB 多估成 4–5 层（12.6–15 m）。
- **重跑时起点被污染**：上一轮写回的小区层数带实测位，从当前文件起算会反过来参与“同型楼同高”验证
  （验证率由 458/613 = 74.7% 变成 1041/1355 = 76.8%，越过 75% 门槛误启用组内统一，连带改动约 600 栋）。本轮改为逐栋回到备份的原始高度/flags 起算
  （轮廓已被其他工作局部更新，按质心 1.5 m + 面积差 5% 对应；对不上的新轮廓用 `data-src/backup/buildings.bin.before_estates`，
  它由当时文件生成并撤回了上一轮的 1167 栋小区层数改动）。

### 8.2 结果

- 新核实小区 **217** 个（high 132 / medium 85；其中 19 个为“点位模式”：小区落在一整片无名大地块里，按房天下点位取最近 N 栋），
  老 93 条补了记录频次；本轮共 287 个小区参与分配（新 205 个有楼可配）。层数未查到的 481 个（房天下成交接口限流）列在 `residential_unverified.json`，保持原高度。
- 片区：高新 63、南门外—小寨—电视塔 28、曲江 8、南二环 8、城墙内 2、其余（经开/未央/莲湖/长安/浐灞等）108（按世界坐标粗分）。
- buildings.bin 相对修改前文件净变化 **5956 栋**（升 4856、降 1100）：小区层数 5914 栋，另 42 栋回到原始值（上一轮抬高、本轮无依据支持，如 < 250 m² 的高层小轮廓）。
- 按原始 CMAB 高度计，本轮小区层数共分配 6389 栋。审计报告：`research/audit/heights_report.md`（“小区真实层数”表与“常识检查”表），
  每个小区的档位与分配：`research/audit/estate_floors.json`。

### 8.5 卫星核对（7 个小区、56 栋）

纯高层小区里 CMAB 只有 4–11 层的轮廓，档案只能说明“小区都是高层”，说不清是哪几栋（可能是会所/底商/幼儿园，也可能是被低估的高楼），
规则上不动。对曲江、高新几个显眼的小区逐个看了 Esri z18 核对图（拼图 `estates_floors_satcheck.jpg`：红线为小区边界，黄框为已按记录分配层数的楼，
青框为未分配、橙框为分配 <18 层的候选，编号与档案 `sat_note` 一致），
只收“落在高层楼排上、轮廓内影像为明亮屋面（暗像素 ≤ 35%）”的轮廓，写进档案 `floors_check.sat_high_xz`（轮廓内一点）并附 `sat_note`：
曲江华著中城 20、中国铁建万科翡翠国际 12、金地西沣公元 10、曲江龙邸 6、曲江观邸 4、万科东方传奇 2、华侨城·天鹅堡 2。
这些楼取本小区 ≥18 层记录的加权中位层数。东方传奇、天鹅堡等小区不少候选框落在楼间阴影里（疑似 CMAB 伪轮廓），宁可不改。

### 8.7 仍存疑

- **城墙内/老城覆盖少**：城墙内住宅地块多为一整片无名大地块，只能走点位模式；房天下成交接口在连续请求后整段限流，
  本轮只拿到城墙内 2 个、南门外—小寨—电视塔 28 个；481 个小区“未查到”（清单可补抓）。
- **名次对应的不确定性**：同一档里具体哪栋是 17 层、哪栋是 28 层没有逐栋依据，只保证“CMAB 越高 → 层数越高”；
  天地源·枫林绿洲、保亿风景御园、曲江观邸、融创西安宸院等有较多“降档”（按记录频次，17/18 层比上一轮估计的多），可能偏保守。
- **CMAB 伪轮廓/切碎/合并**：楼间阴影里的伪轮廓会按档位得到层数（例：盛世长安楼排北侧一串 11 层估值的轮廓），合并的大轮廓（> 2500 m²）不按高层抬；
  轮廓本身不在本轮范围。
- **卫星核对只做了 7 个小区**；`satprio` 统计还有约 100 个“记录 ≥85% 为 18 层以上、却有 ≥4 个 CMAB 低矮轮廓”的小区没看。
- **翡翠国际 44 层、开元第一城 40 层**按成交记录，未逐栋核实是哪几栋。
- **点位模式** 19 个小区：回测约 10% 可能取到紧邻的同类楼。
- CMAB 缺整栋（影像早于建成）的小区（碧桂园云顶、浐灞天睦城、绿地国际生态城高层等）改不了，要等轮廓数据。
