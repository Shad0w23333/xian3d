# 各模块 draw call 盘点（2026-10-06）

生成工具：`tools/check_drawcalls.mjs`（差分法）。对同一机位分别加载 `modules=none`（基线：地形 + 天空 + 后期）和 `modules=X`（只加载一个模块），
二者之差即该模块的 draw call / 三角形增量；另外加载一次全场景作为对照。一次页面加载内依次切换 10 个预设视角（瞬移 + 等影像/近景建筑稳定 + 12 帧取中位数）。

```bash
node tools/check_drawcalls.mjs                                  # 10 个预设视角（白天 time=15，q=2，1280×720）
node tools/check_drawcalls.mjs --views 6 --time 20.8 --modules qujiang,datang
node tools/check_drawcalls.mjs --ll 108.98745,34.19616,150,108.98445,34.19836,30 --time 14.5   # 自定义机位（同 shot.mjs）
node tools/check_drawcalls.mjs --method skip --out docs/PERF_DRAWCALLS.md                   # 慢但更准：全场景 − skip=X
```

口径说明：
- `calls` = `renderer.info.render.calls`，与 `shot.mjs` 控制台 JSON 一致，**含阴影贴图通道**（每个投影网格再画一次）和后期全屏通道（约 6 次）。
- isolate 法下通用建筑/植被不会给未加载的地标让位，所以“各模块之和 + 基线”比全场景高 1~5%（最后一行可对照残差）。
- 机器：M4 Max（Metal），1280×720，q=2（高），`online=0`。

改前 W 酒店机位的 866 次拆解（逐子对象单独显示测得）：湖面倒影 **538**（269 个倒影网格，“透明 + 双面”材质被 three 画两遍）、
园林建筑簇 25 个 THREE.LOD 约 **250**（每簇远景级 8~12 个网格 + 阴影通道）、园门岛亭小品 34（22 个网格，11 个 InstancedMesh）、
阅江楼 33（detail 1 共 19 个网格）、紫云楼 10、驳岸 3。

改后：
- **倒影**：每个湖按 solid / emit / glow 合并成 ≤ 3 个网格（`mergeReflections`，几何复制为世界坐标，InstancedMesh 逐实例展开），材质 `forceSinglePass = true`。269 → 6 个网格、538 → 6 次。
  顺带修了一个旧 bug：原来对 LOD 子级（紫云楼、阅江楼、各簇远景）调用 `obj.updateMatrixWorld(true)` 时父级矩阵尚未更新，倒影几何落在世界原点、被湖面遮罩整体丢弃——
  draw call 照付但画面上只有岛亭/驳岸灯的倒影。现在先 `root.updateMatrixWorld(true)` 再复制，紫云楼、阅江楼、园内殿阁的倒影都出来了（见 `shots/qujiang/after/yue_night_qj.png`）。
- **园内建筑簇**：近景（detail 1）仍按 320 m 格网每簇一个 Group，只在 420 m 内显示；远景（detail 0）25 簇合并成一套网格（`ClusterFarSet`，每种材质 1 个，共 10 个），
  每簇的索引段保留，近景簇 / 超过 6500 m 的簇通过重建索引（`setDrawRange` + 一次 `bufferSubData`）剔除，LOD 切换距离与原 THREE.LOD 完全一致。约 250 → 16 次。
- 小品 builder 关掉实例化（22 → 12 个网格）、阅江楼关掉实例化（19 → 12）、紫云楼 `minInstances: 48`（`buildArch` 新增可选参数透传）。
- 画面：四个目标机位改前/改后逐像素比对，差异像素（>8/255）0.07%~0.30%，全部落在湖面（倒影恢复）和水幕灯光秀（随时间动画）区域；建筑本身逐像素一致。
  代价：倒影几何由共享改为复制（约 2.5M 顶点、60 MB 显存）；远景合并集的几何也是一份独立拷贝（约 0.7M 三角形）。
